<knowledge_rules>

<rule id="Eager_Dispatch_Latency_Eradication">

Assert: if execution_mode == "eager": Launching dozens of small PyTorch/cuTile operators in every layer at every step generates significant host dispatch latency (~2-3 ms per token).

Action: Capture the entire decode forward pass (attention kernel, projections, LayerNorm, cache scatter) into a static CUDAGraph. Replay via graph.replay() to achieve up to 5.28x speedup.

<rule id="Static_KV_Cache_Enforcement">

Assert: if kv_cache_policy == "dynamic_concat" (using torch.cat): Resizing KV cache at each step triggers GPU memory reallocation, fragmentation, and CUDA synchronization.

Action: Pre-allocate a contiguous static GPU cache buffer [Batch, Heads, MaxSeqLen, HeadDim] on startup. Update using in-place scatter_ operator with a pre-allocated index tensor to support Graph Capture compatibility.

<rule id="Zero_SDPA_Fallback_Causal_Padding">

Assert: if sequence_length < 64 during prefill: Block/tile boundary mismatch in cuTile FMHA kernel triggers fallback to PyTorch native SDPA.

Action: Apply causal padding to Q, K, and V along the sequence dimension up to 64. Since the attention is causal, future slots (>= seq_len) are completely masked out. Slice the final output tensor back to the original sequence length.

<rule id="FFN_Linear_Library_Optimal">

Assert: if ffn_backend == "cutile_fused": Custom fused FFN kernels struggle to match cuBLAS/CUTLASS assembly-level Tensor Core optimization for standard GEMM shapes.

Action: Maintain PyTorch's native nn.Linear (which calls cuBLAS) for the FFN block. Since CUDA Graph already eliminates operator dispatch overheads, custom MLP fusion is redundant.

<rule id="TTFT_Cache_Clear_Optimization">

Assert: if execution_mode == "cuda_graph" and TTFT_latency_spike == True: Resetting the pre-allocated cache via eager fill_(0.0) launches and post-hoc copy loops degrades prefill latency by ~1.2ms.

Action: Eliminate fill_(0.0) operations (stale future slots are naturally masked out by causal mask). Modify the prefill attention forward pass to write K/V projections directly into the static cache slices in-place.

<milestones>

<stage id="1_cuTile_Attention_Raw" complexity="Medium">

Dynamic KV Cache를 이용한 Eager cuTile 연산 단계

병목 (Bottleneck): 런타임 JIT 컴파일러 룩업 및 PyTorch C++ Dispatch 계층의 론칭 오버헤드.

해결 (Solution): Causal padding을 적용하여 PyTorch SDPA 폴백을 배제하고 cuTile FMHA 커널 직접 기동.

<code_primitive lang="python">
# Causal padding for sequence lengths not divisible by 64
if T < 64:
    pad_len = 64 - T
    q = F.pad(q, (0, 0, 0, pad_len))
    k = F.pad(k, (0, 0, 0, pad_len))
    v = F.pad(v, (0, 0, 0, pad_len))
    
# Launch cuTile FMHA
out = cutile_fmha_prefill(q, k, v, scale, causal=True)

# Slice back to original length
if T < 64:
    out = out[:, :, :T, :]

<stage id="2_cuTile_CUDA_Graphs" complexity="Extreme">

Static KV 캐시, CUDAGraph Capture, 그리고 TTFT 최적화 결합 단계

병목 (Bottleneck): 매 토큰 생성 시 파이썬 API/ctypes 드라이버 오버헤드와 KV 캐시 재할당 지연.

해결 (Solution): 정적 메모리 버퍼 생성 및 CUDA Graph 캡처 구축, TTFT를 단축하는 direct-writing 최적화 적용.

<code_primitive lang="python">
# 1. In-place Static KV Cache update using scatter_
self.static_k[layer_idx].scatter_(2, self.static_scatter_index, new_k)
self.static_v[layer_idx].scatter_(2, self.static_scatter_index, new_v)

# 2. CUDA Graph Capture
g = torch.cuda.CUDAGraph()
# Warmup before capture
for _ in range(3):
    static_logits = model(static_input, static_kv_cache)
# Record
with torch.cuda.graph(g):
    static_logits = model(static_input, static_kv_cache)

# 3. Direct Prefill Cache Writing (TTFT optimization)
# Pass static_kv buffer directly to the prefill phase forward pass
def forward(self, x, static_kv=None, step_idx=None):
    q, k, v = self.qkv_projection(x)
    if static_kv is not None:
        # Direct write to buffer slice
        static_kv[0].copy_(k)
        static_kv[1].copy_(v)
