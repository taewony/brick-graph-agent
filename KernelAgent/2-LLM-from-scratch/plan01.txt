  Analyzing Parity Testing
  Yes! Parity is verified at two different levels in the codebase:

  ### 1. End-to-End Token Sequence Parity Test

  In compare_infer.py, the script performs an end-to-end verification of the generated token sequences:

    tokens_match = (pt_tokens == cu_tokens)
    print(f"Generated Tokens Match Check: {'PASSED' if tokens_match else 'FAILED'}")

  Since the models use greedy decoding on the same prompt and start with identical weights (
  model_cu.load_state_dict(model_pt.state_dict()) ), this verifies that any differences in attention outputs (due to
  custom tiling or floating point accumulation) do not alter the final output tokens.
  ──────
  ### 2. Attention Layer-Level Mathematical Parity Test

  In cutile_kernel.py, the script contains a correctness check in the  __main__  block that compares the raw outputs of
  the cuTile kernel (cutile_kernel.py) directly against PyTorch's native FlashAttention implementation
(cutile_kernel.py)
  using  torch.testing.assert_close :

    # From cutile_kernel.py:
    print("\n--- Test 2: Causal Attention ---")
    out = cutile_fmha(Q=Q_input, K=K_input, V=V_input, tile_m=args.tile_m, tile_n=args.tile_n, causal=True)
    if args.correctness_check:
        ref = torch_fmha(Q_input, K_input, V_input, is_causal=True, enable_gqa=False)
        torch.testing.assert_close(out, ref, atol=1e-3, rtol=1e-3)
        print("Correctness check passed")

  You can run this specific attention-level parity test by executing:

    python src/cutile_kernel.py --correctness-check
