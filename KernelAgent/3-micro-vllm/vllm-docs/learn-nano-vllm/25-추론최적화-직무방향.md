## 2. 직무별 요구 기술 분석

### 1. 추론 프레임워크 및 시스템 (vLLM / SGLang / 사내 개발)

- **공통점**: **연속 배치 처리, KV Cache, PagedAttention, 스케줄링 및 메모리 풀**을 이해하고, 소스 코드를 읽을 수 있으며, 2차 개발 또는 플러그인을 수행할 수 있어야 합니다.
- **nano-vllm 연결점**: `Scheduler`, `BlockManager`, `ModelRunner`, `Attention` 네 레이어의 협업을 통독하고, **요청 접수부터 step 출력까지**의 데이터 흐름을 그릴 수 있어야 합니다.

### 2. CUDA / 연산자 / 커널

- **공통점**: 커널 융합, 메모리 병합 접근, PyTorch/Triton과의 연계; 일부 직무에서는 **TensorRT** 또는 **CUTLASS**를 강조합니다.
- **nano-vllm 연결점**: `layers/attention.py`의 **Triton `store_kvcache_kernel`**; FlashAttention 인터페이스와 `slot_mapping`의 협업 이해.

### 3. C++ 및 온라인 엔지니어링

- **공통점**: 고성능 서비스, 멀티스레드/멀티프로세스, GPU 드라이버 및 추론 Runtime과의 통합.
- **nano-vllm 연결점**: 파이썬 측에서는 **멀티프로세스 TP**(`ModelRunner` + `SharedMemory` + `Event`)의 설계 이해를 보충하고, C++ 서비스 레이어로 이전 시의 인터페이스 분할 구상을 설명할 수 있습니다.

### 4. 성능 지표 및 방법론

- **공통점**: **처리량(tokens/s)**, **첫 토큰 지연(TTFT)**, **단계별 decode 지연**, 메모리 사용량 및 OOM 경계.
- **nano-vllm 연결점**: `LLMEngine.generate` 내 prefill/decode 처리량 통계 방식; `gpu_memory_utilization`과 `num_kvcache_blocks`의 관계.

## 3. nano-vllm 프로젝트 경험을 위 직무에 매칭하는 방법

이력서와 면접에서 **「문제 → 방안 → 코드 구현 위치 → 지표」** 순으로 서술하는 것을 권장합니다. 예를 들어:

1. **KV Cache와 메모리**: `allocate_kv_cache`가 어떻게 피크 메모리, `block_bytes`로 블록 수를 유도하는지 설명; 텐서 shape `[2, L, B, block_size, kv_heads, head_dim]`과 레이어별 바인딩 방식.
2. **PagedAttention과 프리픽스 캐시**: `BlockManager.compute_hash`의 체인 프리픽스 해시, `allocate` 내 cache hit과 `ref_count`의 협업 설명.
3. **연속 배치 처리와 선점**: `schedule` 내 **prefill 우선**, decode 단계에서 `can_append` 실패 시의 `preempt`와 `deallocate` 설명.
4. **FlashAttention 이중 경로**: prefill 시 `flash_attn_varlen_func` 사용, decode 시 `flash_attn_with_kvcache` 사용, 그리고 `cu_seqlens_*`와 `block_table`의 의미.
5. **텐서 병렬화**: `ColumnParallelLinear` / `RowParallelLinear` / `QKVParallelLinear` 샤딩과 `all_reduce`, `ParallelLMHead`의 `gather`.
6. **CUDA Graph**: decode 전용, 이산 `graph_bs`, `enforce_eager`와의 선택.

이렇게 하면 "toy 프로젝트를 읽었다"는 수준을 **「프로덕션급 추론 시스템 모듈과 연결 가능한」** 서사로 발전시킬 수 있습니다.

## 4. 신입 vs 경력 차이 (추론 방향)

| 차원 | 신입에서 주로 보는 점 | 경력에서 주로 보는 점 |
|------|----------------|----------------|
| 기초 | 자료구조, 운영체제, 네트워크, 머신러닝 기초 | 과거 프로젝트 심도, 온라인 문제 해결 |
| 시스템 | 원리를 명확히 설명 + 간단한 코딩 | 단대단 최적화 사례, 자원 및 SLA |
| 엔지니어링 | 코드 규범, 학습 능력, 인턴십 | 안정성, 협업, 전달 리듬 |
| 급여 | 등급별 고정 급여 + sp/ssp | 연차, 직급, 팀과 밀접한 관련 |

신입 지원자는 **소스 코드 리딩 + 소규모 실험(bench) + 명확한 그림**을 강조할 수 있으며, 경력 지원자는 **병목 진단 방법, 데이터, 복기**를 준비해야 합니다.

## 5. 급여 범위 분석 (참고만 하세요)

- **일선 인터넷 / 대규모 모델 사업**: 신입 총 보수 편차가 크며, 학력, 인턴십, 면접 성과와 밀접한 관련이 있습니다. 추론 방향이 **GPU, 커널, 엔진**과 강하게 결합되면, 종종 **R&D 급여 대역 중상위권**에 속합니다.
- **전문가 / 아키텍트**: 월급 구간은 흔히 **수만에서 십여만**까지이며, 보통 스톡/옵션과 성과가 포함됩니다. 표의 '5–7만/월' 등은 **업계 통상 범위**이므로, 실제 오퍼를 기준으로 합니다.
- **지역**: 베이징, 상하이, 선전, 항저우가 보통 다른 도시보다 높습니다. 같은 회사라도 베이스가 다르면 차이가 있습니다.

**권장**: '급여'를 정보 검색과 협상의 참고용으로 사용하고, 면접 준비는 여전히 **기술 깊이와 프로젝트 매칭도**에 집중하세요.

---

## 6. 요약

추론 최적화 직무는 **고도의 교차 분야**(시스템 + 모델 + GPU)이며, nano-vllm은 **최소 폐쇄 루프**로서 적합합니다: `LLMEngine`에서 `Attention`까지 전 파이프라인을 디버깅할 수 있고, 코드 양도 관리 가능합니다. 구직 시 **스케줄링, 메모리, 어텐션, 병렬화, 그래프 캡처** 다섯 가지 주요 라인을 명확히 설명하고, 각각 1~2곳의 소스 코드 행 번호 또는 함수명을 대응시키면, 막연한 'vLLM을 안다'는 표현보다 훨씬 강한 인상을 줄 것입니다.
