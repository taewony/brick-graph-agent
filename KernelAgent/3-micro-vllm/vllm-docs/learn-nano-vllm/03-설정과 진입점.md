# 강의 03: 설정과 진입점

> `Config`와 `SamplingParams` 두 dataclass를 통해 엔진의 GPU 메모리 및 배치 경계를 파악하고, `example.py`를 따라가며 "로컬 모델 디렉터리 → LLM → generate"를 실행하고 면접에서 모든 줄을 설명할 수 있게 됩니다.

## 본 강의 목표

1. `Config`를 **필드별로** 이해: 모델 경로, batch/token 상한, TP, KV 블록, `enforce_eager` 등.
2. `SamplingParams`를 **필드별로** 이해: temperature, `max_tokens`, `ignore_eos` 및 assertion 뒤의 설계적 선택.
3. **`example.py`**를 단계별로 설명 가능: `apply_chat_template` → `LLM` → `generate` → 출력.
4. **면접 멘트** 구축: 왜 `max_num_batched_tokens >= max_model_len`인지, 왜 greedy(temperature 하한)를 지원하지 않는지.

## 핵심 개념

### Config: 엔진의 '물리적·스케줄링적 경계'

`Config`는 초기화 단계에서 **`LLMEngine` / `ModelRunner` / `BlockManager`**에 의해 소비되며 다음을 결정합니다:

- **디스크에서 어떤 모델을 로드할 수 있는지** (`model` 디렉터리 + `hf_config`).
- **한 번의 순전파에서 최대 몇 개의 토큰을 계산하는지** (`max_num_batched_tokens`).
- **최대 몇 개의 시퀀스를 동시에 처리하는지** (`max_num_seqs`).
- **단일 시퀀스의 최대 길이가 얼마인지** (`max_model_len`, HF의 `max_position_embeddings`와 min 값을 취함).
- **KV를 어떤 단위로 페이징할지** (`kvcache_block_size`) 및 **블록 수** (`num_kvcache_blocks`, 보통 GPU 메모리로 추산).
- **텐서 병렬 처리의 정도** (`tensor_parallel_size`) 및 **GPU 메모리 활용률** (`gpu_memory_utilization`).
- **CUDA Graph 사용 여부** (`enforce_eager`).

`Config`는 **"하드웨어와 SLA를 파이썬 숫자로 변환"**하는 계층으로 이해할 수 있습니다.

### SamplingParams: 디코딩 전략 (사용자 측)

**엔진 자원**과는 직교하는 개념으로, `SamplingParams`는 **logits에서 어떻게 다음 토큰을 샘플링할지**를 설명합니다:

- **temperature**: 분포를 '평평하게' 할지 '뾰족하게' 할지 제어; 본 프로젝트에서는 **0을 허용하지 않습니다** (assertion 참고).
- **max_tokens**: **최대 몇 개의 신규 토큰**을 생성할지 (프롬프트 길이와는 별도로 이해).
- **ignore_eos**: 참이면, EOS 토큰을 만나도 계속 생성합니다 (압력 테스트나 특수 시나리오에 사용).

### example.py: 최소 실행 가능 스크립트

전형적 흐름:

1. **로컬 HuggingFace 형식의 모델 디렉터리** 지정 (내부에 `config.json`, 가중치 등 포함).
2. **`AutoTokenizer`**로 어휘 및 chat 템플릿 로드.
3. 사용자 문장을 **대화 형식 문자열**로 포장 (`apply_chat_template`).
4. **`LLM`**과 **`SamplingParams`**을 구성하고 **`generate`** 호출.
5. **`outputs`**를 순회하며 **`output['text']`** 읽기 (구체적인 키 이름은 저장소 기준).

## 소스 코드 분석 (전체 소스 코드 및 줄별 주석 포함)

### 1. `config.py`

```python
import os
from dataclasses import dataclass
from transformers import AutoConfig


@dataclass
class Config:
    model: str
    max_num_batched_tokens: int = 16384
    max_num_seqs: int = 512
    max_model_len: int = 4096
    gpu_memory_utilization: float = 0.9
    tensor_parallel_size: int = 1
    enforce_eager: bool = False
    hf_config: AutoConfig | None = None
    eos: int = -1
    kvcache_block_size: int = 256
    num_kvcache_blocks: int = -1

    def __post_init__(self):
        assert os.path.isdir(self.model)
        assert self.kvcache_block_size % 256 == 0
        assert 1 <= self.tensor_parallel_size <= 8
        self.hf_config = AutoConfig.from_pretrained(self.model)
        self.max_model_len = min(self.max_model_len, self.hf_config.max_position_embeddings)
        assert self.max_num_batched_tokens >= self.max_model_len
```

**줄별/필드별 설명**:

| 코드 위치 | 의미 | 왜 이렇게 설계했는가 |
|----------|------|----------------------|
| `@dataclass` | `__init__` 등을 자동 생성 | 설정 클래스는 필드가 많아 dataclass가 보일러플레이트 코드를 줄임 |
| `model: str` | 로컬 모델 디렉터리 경로 | 가중치와 HF `config` 모두 이 디렉터리에서 읽음, **반드시 디렉터리**여야 함 |
| `max_num_batched_tokens` | 단일 순전파 **배치 내 토큰 총 수** 상한 | 연산자 입력 규모 제한, OOM 방지; **가장 긴 단일 시퀀스**를 커버할 수 있어야 함 |
| `max_num_seqs` | 동시 **시퀀스 개수** 상한 | 연속 배치 처리에서 "동시에 서비스할 요청 수"와 관련 |
| `max_model_len` | 단일 시퀀스 **최대 컨텍스트 길이** | KV, 블록 테이블, 스케줄링과 관련; 모델 위치 인코딩 상한을 초과할 수 없음 |
| `gpu_memory_utilization` | **GPU 메모리 중 어느 정도 비율**을 KV 등에 사용할지 | 프레임워크, 파편화, 임시 텐서를 위한 여유분 남김 |
| `tensor_parallel_size` | **텐서 병렬** 카드 수 | 가중치와 텐서 분할, 값 범위 1~8은 구현 가정과 일치 |
| `enforce_eager` | **True**이면 CUDA Graph 미사용, 디버깅 편리 | Graph 캡처 후 디버깅 어려움; 개발 기간에 흔히 True로 설정 |
| `hf_config` | HuggingFace `AutoConfig` 객체 | 레이어 수, 헤드 수, `max_position_embeddings` 등 읽기 |
| `eos` | 종료 토큰 id, 기본값 -1은 추후 설정 의미 | 어휘, 샘플링 종료 조건과 정렬 |
| `kvcache_block_size` | **KV 페이징 블록 크기** (토큰 단위 관련) | PagedAttention 개념; **256의 배수**여야 함 (커널/정렬 관련) |
| `num_kvcache_blocks` | 총 블록 수, -1은 보통 자동 계산 의미 | 메모리 활용률과 블록 크기를 결합하여 풀 크기 추산 |
| `assert os.path.isdir(self.model)` | 경로가 반드시 디렉터리 | 파일 경로를 모델 루트 디렉터리로 오인하는 것 방지 |
| `kvcache_block_size % 256 == 0` | 정렬 제약 | Triton/CUDA 커널 어드레싱과 블록 매핑 단순화 |
| `tensor_parallel_size` 1~8 | 병렬 구현과 일치 | 지원하지 않는 world size 전달 방지 |
| `AutoConfig.from_pretrained` | `config.json` 가져오기 | Transformers 생태계와 정렬, 하이퍼파라미터 수동 작성 줄임 |
| `max_model_len = min(...)` | 사용자 설정과 모델 능력 중 **더 작은 값** 선택 | 요청이 **학습/위치 인코딩** 상한을 초과하는 것 방지 |
| `max_num_batched_tokens >= max_model_len` | **스케줄링 가능성**: 최소한 **한 번의 prefill에서 전체 길이의 프롬프트 하나를 처리할 수** 있어야 함 | 그렇지 않으면 극단적인 경우 초장문 단일 요청에 합리적인 배치를 할당할 수 없음 |

### 2. `sampling_params.py`

```python
from dataclasses import dataclass


@dataclass
class SamplingParams:
    temperature: float = 1.0
    max_tokens: int = 64
    ignore_eos: bool = False

    def __post_init__(self):
        assert self.temperature > 1e-10, "greedy sampling is not permitted"
```

**줄별 설명**:

| 코드 | 의미 | 설계 설명 |
|------|------|----------|
| `temperature: float = 1.0` | 기본 **표준 softmax 온도** | 1.0은 '모델 출력 분포대로 샘플링'하는 일반적 기준 |
| `max_tokens: int = 64` | 기본 최대 **신규 생성 토큰 64개** | 무한 생성 방지; 실무에서는 종종 더 크게 조정 |
| `ignore_eos: bool = False` | 기본적으로 **EOS 만나면 중지** | True면 조기 종료 무시에 사용 |
| `temperature > 1e-10` | **temperature=0(greedy) 금지** | greedy는 `argmax` 분기와 수치적 디테일 필요; 교육용 프로젝트에서 인터페이스를 좁혀 샘플링 구현의 분기를 피함 |
| assertion 문구 `greedy sampling is not permitted` | 호출 측에 명확히 알림 | 면접에서 이렇게 말할 수 있음: **샘플링 경로 단순화, 온도 샘플링으로 통일** |

### 3. `example.py`

```python
import os
from nanovllm import LLM, SamplingParams
from transformers import AutoTokenizer


def main():
    path = os.path.expanduser("~/huggingface/Qwen3-0.6B/")
    tokenizer = AutoTokenizer.from_pretrained(path)
    llm = LLM(path, enforce_eager=True, tensor_parallel_size=1)

    sampling_params = SamplingParams(temperature=0.6, max_tokens=256)
    prompts = [
        "introduce yourself",
        "list all prime numbers within 100",
    ]
    prompts = [
        tokenizer.apply_chat_template(
            [{"role": "user", "content": prompt}],
            tokenize=False,
            add_generation_prompt=True,
        )
        for prompt in prompts
    ]
    outputs = llm.generate(prompts, sampling_params)

    for prompt, output in zip(prompts, outputs):
        print("\n")
        print(f"Prompt: {prompt!r}")
        print(f"Completion: {output['text']!r}")


if __name__ == "__main__":
    main()
```

**줄별 설명**:

| 행/블록 | 역할 |
|--------|------|
| `expanduser("~/...")` | 홈 디렉터리 확장, **여러 머신에서 이식 가능** |
| `AutoTokenizer.from_pretrained(path)` | 동일한 모델 디렉터리에서 **어휘 및 special tokens** 로드 |
| `LLM(path, enforce_eager=True, tensor_parallel_size=1)` | 엔진 구성: `path`는 `Config.model`로 전달; **eager**는 디버깅 편의; **TP=1** 단일 카드 |
| `SamplingParams(temperature=0.6, max_tokens=256)` | 1보다 약간 낮은 온도 = **약간 더 날카로운** 분포; 더 긴 답변 허용 |
| `prompts` 리스트 | 원시 사용자 문장 |
| `apply_chat_template(..., tokenize=False, add_generation_prompt=True)` | **Qwen/chat** 형식에 맞춰 **단일 문자열**로 조합 (`<|im_start|>` 등 포함), **일단 id로 변환 안 함** (tokenize는 엔진 측 또는 후속 단계에서, 저장소 기준) |
| `llm.generate(prompts, sampling_params)` | **핵심 진입점**: 내부에서 tokenize + 스케줄링 + 순전파 + 샘플링 |
| `output['text']` | **생성 텍스트** 가져오기 (로컬 버전에서 키 이름이 다르다면 실제 `llm_engine` 반환값 기준) |

## 그림 설명 (텍스트/ASCII 설명)

**설정 주입 관계**:

```
path (디렉터리)
   |
   +---> AutoTokenizer  (어휘, chat 템플릿)
   |
   +---> Config.model  (HF config + 가중치 경로)
            |
            v
        LLM / LLMEngine / ModelRunner / BlockManager
```

**example 데이터 흐름**:

```
원시 프롬프트
    -> apply_chat_template -> 문자열 (역할 마크 포함)
    -> LLM.generate
    -> [출력 dict 리스트] -> text 출력
```

## 면접 출제 포인트

- **`max_num_batched_tokens`과 `max_model_len`의 부등식**: 극단적인 **단일 요청 prefill**도 스케줄링 가능함을 보장 (개념 문제 빈출).
- **`kvcache_block_size` 256 정렬**: **커널 및 메모리 정렬** 사고를 반영.
- **`enforce_eager`**: CUDA Graph와 **디버깅/동적 shape**의 트레이드오프.
- **`SamplingParams` greedy 금지**: **인터페이스 단순화**와 **구현 통일**.
- **`temperature` 극소값**: 수치 안정성과 **샘플링 경로 단일화**.

## 자주 나오는 면접 질문

1. **`max_model_len`을 HF의 `max_position_embeddings`보다 크게 설정하면 어떻게 되나요?**  
   답변: **`min`에 의해** 모델 상한으로 잘려, 위치 인코딩 능력을 초과할 수 없습니다.

2. **왜 단일 카드에서도 `tensor_parallel_size=1`이라고 명시해야 하나요?**  
   답변: **world size**를 명시적으로 표현하여, 분산 초기화와 레이어 구현이 단일 분기로 통일될 수 있습니다.

3. **`gpu_memory_utilization`을 크게 조정하면 어떤 위험이 있나요?**  
   답변: KV 풀 또는 기타 버퍼가 **OOM에 더 가까워짐**; 배치 및 동시 요청과 결합하여 평가해야 합니다.

4. **`apply_chat_template`는 추론 엔진 안에서 하는 것이 나을까요, 밖에서 하는 것이 나을까요?**  
   답변: nano-vllm 예제에서는 **엔진 밖**에서 합니다. 서비스 API에서는 흔히 서버 측에서 통합 처리하며, **엔진은 오직 토큰 id만 받습니다** — **경계가 명확하다**고 답변할 수 있으면 충분합니다.

## 요약

- `Config`는 **얼마나 큰 배치, 얼마나 긴 시퀀스, 얼마나 많은 동시 요청, KV를 어떻게 페이징할지**를 정의합니다. `__post_init__`이 **HF 능력**과 **사용자 설정**을 정렬합니다.
- `SamplingParams`는 **디코딩 동작**을 정의합니다. **temperature=0을 금지**하여 샘플링 구현 범위를 좁힙니다.
- `example.py`는 **Tokenizer + LLM + 대화 템플릿**의 표준 조합을 보여주며, **실행 및 면접 설명**의 첫 번째 자료가 됩니다.
