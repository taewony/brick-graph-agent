# 01. nano-vllm 소개: 왜 vLLM인가?

> LLM(거대 언어 모델) 서비스를 운영할 때 가장 큰 고민은 **"어떻게 하면 적은 비용으로 더 많은 사용자에게 빠르게 응답할 것인가?"**입니다. 이 문서는 `nano-vllm` 코드베이스를 통해 그 해답을 찾아가는 첫걸음입니다.

---

## 1. LLM 추론의 핵심 난제: KV Cache

LLM이 문장을 생성할 때, 이전에 생성한 단어들의 정보를 기억하기 위해 **KV Cache(Key-Value Cache)**라는 메모리 공간을 사용합니다. 

*   **문제점**: 모델이 커질수록, 그리고 답변이 길어질수록 KV Cache가 차지하는 메모리 양은 기하급수적으로 늘어납니다.
*   **비효율성**: 기존 방식은 각 요청마다 "최대 길이(Max Sequence Length)"만큼 메모리를 미리 예약해 둡니다. 하지만 실제 답변은 그보다 훨씬 짧은 경우가 많아, 전체 메모리의 **60~80%가 낭비**되기도 합니다.

## 2. vLLM의 혁신: PagedAttention

vLLM은 운영체제의 '가상 메모리'와 '페이징(Paging)' 기념을 LLM 메모리 관리에 도입했습니다.

1.  **메모리 쪼개기**: 연속적인 커다란 메모리 공간 대신, **블록(Block)**이라는 작은 단위로 메모리를 나눕니다.
2.  **동적 할당**: 단어가 생성될 때마다 필요한 만큼만 블록을 할당하고 연결합니다.
3.  **파편화 제거**: 이를 통해 메모리 낭비를 거의 0%에 가깝게 줄였고, 결과적으로 **동시 사용자 처리량(Throughput)을 수 배~수십 배** 끌어올렸습니다.

## 3. 왜 nano-vllm을 공부해야 할까요?

실제 [vLLM](https://github.com/vllm-project/vllm) 프로젝트는 수만 줄의 복잡한 C++/CUDA/Python 코드로 구성되어 있어 입문자가 내부 원리를 파악하기 매우 어렵습니다.

**`nano-vllm`은 다음과 같은 특징을 가집니다:**
*   **최소한의 구현 (Minimalistic)**: vLLM의 핵심 로직(PagedAttention, Scheduler, BlockManager)을 수백 줄의 순수 Python/PyTorch 코드로 압축했습니다.
*   **교육용 최적화**: 복잡한 최적화 기법을 걷어내고, "데이터가 어떻게 흐르는가?"와 "메모리가 어떻게 관리되는가?"라는 본질에 집중합니다.
*   **실전 아키텍처**: 작지만 분산 처리(Tensor Parallel)와 효율적인 스케줄링 구조를 그대로 담고 있어, 거대 시스템의 설계를 배우기에 최적입니다.
