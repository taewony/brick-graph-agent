# TDRE: Test-Driven Reverse Engineering

"코드를 수정했는데, 이게 정말 예전과 똑같이 동작할까?" 

LLM 엔진 개발에서 가장 무서운 것은 **'수치적 오류(Numerical Error)'**입니다. 겉보기엔 코드가 잘 돌아가고 텍스트가 나오는 것 같지만, 내부에서 소수점 넷째 자리 숫자가 틀어지면 결국 모델의 답변 품질이 망가지게 됩니다.

---

## 1. TDRE (테스트 주도 역공학)란?

기존의 코드를 분석(Reverse Engineering)하고 재구성할 때, **먼저 테스트 케이스를 만들고 그 숫자를 맞추는 방식**입니다.

1.  **Golden Reference (정답지)**: 이미 검증된 `transformers`나 `torch.nn`의 결과값을 정답으로 삼습니다.
2.  **Surgical Injection (데이터 주입)**: 내 코드의 특정 레이어에 정답지와 똑같은 '가비지 데이터(고정된 랜덤값)'를 넣습니다.
3.  **Numerical Parity (수치적 동등성)**: 두 코드의 출력값이 소수점 아주 깊은 곳까지 일치하는지 확인합니다.

## 2. GIGO (Garbage-In, Garbage-Out) 테스트

우리는 모델의 가중치가 실제 무엇인지 관심이 없습니다. 테스트를 위해 임의의 데이터(Garbage)를 넣어도, **입력이 같다면 출력도 같아야 한다**는 원칙을 이용합니다.

### 테스트 단계:
*   **단계 1: 고정 입력 생성** (Seed를 고정하여 항상 똑같은 랜덤 텐서 생성)
*   **단계 2: 기준 모델 실행** (HuggingFace의 레이어 결과값 저장)
*   **단계 3: 내 모델 실행** (내가 수정한 `nano-vllm` 레이어 결과값 저장)
*   **단계 4: 오차 측정** (`torch.allclose`를 사용하여 미세 오차 이내인지 검증)

---

## 3. 테스트 가능한 핵심 레이어 리스트

| 검증 대상 | 비교 대상 (Golden Ref) | 핵심 검증 포인트 |
| :--- | :--- | :--- |
| **ColumnParallelLinear** | `torch.nn.Linear` | 텐서를 GPU 개수만큼 쪼개서 계산해도 결과가 합쳐졌을 때 같은가? |
| **RowParallelLinear** | `torch.nn.Linear` | All-Reduce 통신 후 결과값이 원본과 일치하는가? |
| **RotaryEmbedding** | 수동 수학 공식 (NumPy/Torch) | 회전 행렬 연산이 위치 인덱스에 맞게 정확히 들어갔는가? |
| **Attention** | `Flash-Attention` | PagedAttention의 블록 단위 계산 결과가 전체 계산과 같은가? |

## 📝 학생들을 위한 요약
*   **확신**: 테스트 통과는 여러분의 "Hacking"이 성공했다는 유일한 증거입니다.
*   **정밀도**: GPU 연산은 `1e-5` 수준의 오차까지 관리해야 합니다.
*   **반복**: 코드를 한 줄 고칠 때마다 이 테스트를 돌려 "숫자가 깨지지 않았음"을 확인하세요.
