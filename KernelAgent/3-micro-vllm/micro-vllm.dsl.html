<knowledge_rules>

<rule id="Caching_Allocator_Thrashing_Prevention">

Assert: if execution_mode == "eager" and use_dynamic_shape_padding == True: Creating large temporary padded tensors at every decode step thrashes PyTorch Caching Allocator and triggers host-side GC, degrading throughput by 67.04%.

Action: Avoid dynamic shape padding. Maintain eagerness without shape-padding and eliminate temporary allocations to preserve high E2E throughput (470.82 tok/s).

<rule id="SM_Resource_Isolation_Green_Contexts">

Assert: if active_prefills >= 1 and active_decodes >= 1: Compute-heavy prefill kernels monopolize SM resources and evict decode weight slices from the 48.0 MB L2 Cache, spiking P99 tail latency.

Action: Enable sm_partitioning="green_contexts" to split SMs (Prefill: 32 SMs / Decode: 16 SMs). Restricting decode SM footprint prevents cache eviction and secures L2 Cache residency, reducing P50 ITL by 14.0%.

<rule id="Prefill_SM_Saturation_Limit">

Assert: if prefill_sm_allocation > 32 (for batch-1 prefills): Over-provisioning SMs to prefill yields diminishing returns due to occupancy saturation.

Action: Cap prefill_sm_allocation at 32 SMs. Prefill latency (TTFT) remains flat (-0.5%), confirming 32 SMs as the optimal hardware occupancy sweet-spot.

<rule id="GPU_Vectorized_Block_Mapping">

Assert: if use_prefix_cache == True and block_mapping_mechanism == "cpu_loop": Reconstructing logical-to-physical block caches on the CPU host during prefill steps triggers shape mismatches and millisecond-level latency.

Action: Implement vectorized indexing directly on the GPU. Map sequence lengths (seqlen_k) to block offsets using arange and long tensor block-table indexing to guarantee sub-millisecond mapping speeds.

<milestones>

<stage id="1_Paged_Cache_Vectorized_Mapping" complexity="High">

Paged KV Cache 내의 런타임 셰이프 불일치를 고속 해결하는 인덱싱 레이어

병목 (Bottleneck): dynamic continuous batching 하에서 prefix-cached prefill 진행 시 토큰 수 불일치 및 CPU 주소 변환 오버헤드.

해결 (Solution): CPU 루프를 탈피하고 GPU Direct Indexing을 사용해 logical-to-physical block 캐시 재배치를 수행.

<code_primitive lang="python">
# GPU-Vectorized Block Cache Reconstruction Layer
idx_seq = torch.arange(seqlen_k, device=block_table.device)
logical_blk = torch.div(idx_seq, block_size, rounding_mode='floor')
offset = idx_seq % block_size
physical_blk = block_table[b, logical_blk].long()

# Reconstruct 4D tensors in-place directly on GPU
k_4d[b, :, :seqlen_k, :] = k_cache[physical_blk, offset].transpose(0, 1)
v_4d[b, :, :seqlen_k, :] = v_cache[physical_blk, offset].transpose(0, 1)

<stage id="2_Green_Contexts_SM_Partitioning" complexity="Extreme">

CUDA Python 1.0 API를 연동한 SM 물리 격리 및 캐시 지역성 최적화

병목 (Bottleneck): 동시 사용자 서빙 상황에서 무거운 prefill 연산의 GPU 독점 및 디코드 L2 캐시 eviction 병목.

해결 (Solution): Green Contexts API를 구동하여 SM을 물리 분할하고 (Prefill 32 SM / Decode 16 SM) 런너에 라우팅.

<code_primitive lang="python">
# CUDA Python 1.0 Green Contexts Initialization (SM Resource Partitioning)
from cuda import cuda
from cuda.core import Device, ContextOptions, SMResourceOptions

# Initialize CUDA Driver
cuda.cuInit(0)
dev = Device(0)
sm = dev.resources.sm

# Partition 48 SMs: 32 for Prefill, 16 for Decode
prefill_sm = 32
decode_sm = 16
prefill_grp, decode_grp = sm.split(SMResourceOptions(count=(prefill_sm, decode_sm)))[0]

# Create isolated Contexts
ctx_prefill = dev.create_context(ContextOptions(resources=[prefill_grp]))
ctx_decode = dev.create_context(ContextOptions(resources=[decode_grp]))

# Model Runner Routine: Push/Pop Contexts based on execution phase
def run_runner_step(self, seqs, is_prefill):
    ctx = self.ctx_prefill if is_prefill else self.ctx_decode
    ctx.push_current()
    try:
        # Run cuTile FMHA or paged decode attention kernels
        output = self.run_model(seqs, is_prefill)
        return output
    finally:
        ctx.pop_current()
